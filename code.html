01 Linear Algebra Matrix factorisation and direct solvers
▶ cholesky Decompose a symmetric positive-definite matrix into LLᵀ C++ Foundational

The Cholesky decomposition factors a symmetric positive-definite matrix A as A = L·Lᵀ, where L is lower-triangular. It is roughly twice as fast as LU and is the standard tool for correlating Gaussian draws in Monte Carlo — if z is a vector of independent standard normals, then L·z has covariance A.

The one subtlety: the algorithm takes a square root of the running diagonal term, so if A is not positive-definite that value goes negative. The implementation checks for this explicitly and throws, rather than silently returning NaN — a non-PD covariance matrix is almost always a data bug worth surfacing.

numerics/cholesky.hpp view on github 
#include <vector>
#include <cmath>
#include <stdexcept>

namespace numerics {

// Cholesky factorisation: A = L * L^T for symmetric positive-definite A.
// Returns the lower-triangular factor L (row-major, n x n).
inline std::vector<std::vector<double>>
cholesky(const std::vector<std::vector<double>>& A) {
    const std::size_t n = A.size();
    std::vector<std::vector<double>> L(n, std::vector<double>(n, 0.0));

    for (std::size_t i = 0; i < n; ++i) {
        for (std::size_t j = 0; j <= i; ++j) {
            double sum = 0.0;
            for (std::size_t k = 0; k < j; ++k)
                sum += L[i][k] * L[j][k];

            if (i == j) {
                const double d = A[i][i] - sum;
                if (d <= 0.0)
                    throw std::runtime_error(
                        "cholesky: matrix is not positive-definite");
                L[i][j] = std::sqrt(d);
            } else {
                L[i][j] = (A[i][j] - sum) / L[j][j];
            }
        }
    }
    return L;
}

} // namespace numerics
▶ lu_decompose LU factorisation with partial pivoting C++ Foundational

LU with partial pivoting factors any non-singular matrix as P·A = L·U. Pivoting — swapping in the row with the largest available element — is what keeps the factorisation numerically stable; without it, a small pivot blows up the error.

02 Root Finding Solvers for f(x) = 0
▶ newton_raphson Quadratically-convergent root finder with a safeguard Python Foundational

Newton-Raphson iterates x ← x − f(x)/f′(x) and converges quadratically near a root. Its weakness is well known: a near-zero derivative sends the next iterate far away. The classic application in finance is the implied volatility solve — inverting the Black-Scholes price for σ — where f′ is vega.

This version takes the derivative as a callable and adds two safeguards: a divide-by-near-zero check on the derivative, and an iteration cap that raises rather than looping forever. Returning a wrong answer silently is worse than failing loudly.

from typing import Callable


def newton_raphson(
    f: Callable[[float], float],
    df: Callable[[float], float],
    x0: float,
    tol: float = 1e-10,
    max_iter: int = 100,
) -> float:
    """Solve f(x) = 0 from initial guess x0.

    Parameters
    ----------
    f, df : the function and its first derivative.
    x0    : starting point.
    tol   : absolute tolerance on |f(x)|.

    Raises
    ------
    RuntimeError
        If the derivative collapses or the iteration cap is hit.
    """
    x = x0
    for _ in range(max_iter):
        fx = f(x)
        if abs(fx) < tol:
            return x

        dfx = df(x)
        if abs(dfx) < 1e-14:
            raise RuntimeError("newton_raphson: derivative too small")

        x -= fx / dfx

    raise RuntimeError(
        f"newton_raphson: no convergence in {max_iter} iterations"
    )
03 Option Pricing Monte Carlo and lattice methods
▶ mc_price Vanilla European pricer with antithetic variates Python Intermediate

A Monte Carlo price is just the discounted average payoff over many simulated terminal prices. Under geometric Brownian motion the terminal price has a closed form, so no time-stepping is needed for a vanilla — one draw per path.

The variance-reduction trick here is antithetic variates: for every draw z we also use −z. Because the payoff is monotone in z, the two are negatively correlated, so their average has lower variance than two independent draws — a free reduction in standard error for one line of code. The function also returns that standard error, because a price without an error bar is only half an answer.

pricing/monte_carlo.py view on github 
import numpy as np


def mc_price(
    s0: float, k: float, r: float, sigma: float, t: float,
    n_paths: int = 100_000, option: str = "call", seed: int | None = None,
) -> tuple[float, float]:
    """Price a European option under Black-Scholes by Monte Carlo.

    Returns
    -------
    (price, std_error) : the estimate and its Monte Carlo standard error.
    """
    rng = np.random.default_rng(seed)

    # Antithetic draws: pair each z with -z.
    z = rng.standard_normal(n_paths // 2)
    z = np.concatenate([z, -z])

    # Terminal price under GBM (exact, no time-stepping needed).
    drift = (r - 0.5 * sigma**2) * t
    diffusion = sigma * np.sqrt(t) * z
    s_t = s0 * np.exp(drift + diffusion)

    if option == "call":
        payoff = np.maximum(s_t - k, 0.0)
    elif option == "put":
        payoff = np.maximum(k - s_t, 0.0)
    else:
        raise ValueError(f"unknown option type: {option!r}")

    discounted = np.exp(-r * t) * payoff
    price = discounted.mean()
    std_error = discounted.std(ddof=1) / np.sqrt(len(discounted))
    return price, std_error
▶ longstaff_schwartz Least-squares Monte Carlo for American/Bermudan options Python Advanced

Pricing an early-exercisable option by Monte Carlo is hard because the exercise decision needs the continuation value — the expected payoff from holding — which is not known forward in time. Longstaff-Schwartz estimates it by regressing realised discounted payoffs against the current state, working backward through time.
